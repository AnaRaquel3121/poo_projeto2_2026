% SECAO 1: INTRODUCAO
\section{Introdução}

O presente documento constitui o manual de utilização e documentação técnica do sistema
de alarme doméstico desenvolvido no âmbito da unidade curricular de Programação Orientada
aos Objetos (POO). Este projeto tem como objetivo simular um sistema de alarme para um
apartamento com cinco divisões, implementando conceitos fundamentais de POO em C++.

\subsection{Enquadramento do Projeto}

O sistema de alarme doméstico é uma aplicação prática que permite a simulação de um
sistema de segurança residencial. O apartamento em causa possui cinco divisões:
Sala, Cozinha, Quarto, Casa de Banho e Entrada. Cada divisão pode ser monitorizada
por sensores especializados que detetam diferentes tipos de eventos.

\subsection{Objetivos do Sistema}

O sistema de alarme foi desenvolvido para satisfazer os seguintes requisitos funcionais:

\begin{itemize}[noitemsep]
    \item \textbf{Gestão de Estados}: O sistema pode estar armado (ativo) ou desarmado (inativo)
    \item \textbf{Autenticação por Senha}: O acesso ao sistema é protegido por uma senha de 4 dígitos
    \item \textbf{Controlo de Campainha}: O alarme sonoro ativa automaticamente após 3 tentativas erradas
    \item \textbf{Monitorização por Sensores}: Sensores de diferentes tipos monitorizam as divisões
    \item \textbf{Processamento de Eventos}: Os eventos são processados sequencialmente (FIFO)
    \item \textbf{Interface Interativa}: Menu de consola para interação direta com o utilizador
\end{itemize}

\subsection{Tipos de Sensores Suportados}

O sistema Supports cinco categorias de sensores, cada uma projetada para detetar
um tipo específico de evento:

\begin{enumerate}[noitemsep]
    \item \textbf{INTRUSÃO}: Sensores de abertura de portas e janelas
    \item \textbf{MOVIMENTO}: Sensores de presença interior (infravermelhos)
    \item \textbf{FOGO}: Sensores de deteção de incêndio (fumo/temperatura)
    \item \textbf{GÁS}: Sensores de fuga de gás natural ou GLP
    \item \textbf{INUNDAÇÃO}: Sensores de inundação (água)
\end{enumerate}

\subsection{Visão Geral da Arquitetura}

O sistema é composto por três classes principais que implementam toda a lógica de
negócio e gestão do alarme:

\begin{itemize}
    \item \textbf{ComandoAlarme}: Central de comando que gere estados, autenticação e campainha
    \item \textbf{Sensor}: Representa cada dispositivo de monitorização nas divisões
    \item \textbf{Simulacao}: Coordena a execução e processa eventos da fila FIFO
\end{itemize}

\section{Arquitetura do Sistema}

\subsection{Diagrama de Classes UML}

A arquitetura do sistema segue o paradigma da orientação a objetos, organizando-se
em três classes principais que implementam os conceitos de composição e associação.

\subsubsection{Classe ComandoAlarme}

A classe \texttt{ComandoAlarme} é a central de comando do sistema, responsável
por toda a lógica de autenticação e controlo de estados.

\begin{table}[h!]
\centering
\begin{tabular}{|l|l|p{7cm}|}
\hline
\textbf{Visibilidade} & \textbf{Atributo} & \textbf{Descrição} \\
\hline
- & estado & Boolean: true=armado, false=desarmado \\
\hline
- & senha & String com a senha de 4 dígitos \\
\hline
- & mensagem & String com a última mensagem do sistema \\
\hline
- & estadoCampainha & Boolean: true=ativa, false=desativada \\
\hline
- & tentativas & Contador de tentativas falhadas \\
\hline
- & MAX\_TENTATIVAS & Constante = 3 \\
\hline
\end{tabular}
\caption{Atributos da classe ComandoAlarme}
\end{table}

\textbf{Métodos públicos:}

\begin{itemize}
    \item \texttt{armar(senha)}: Arma o sistema após validação da senha
    \item \texttt{desarmar(senha): bool}: Desarma o sistema, retorna sucesso
    \item \texttt{mudarSenha(senhaAntiga, senhaNova): bool}: Altera a senha
    \item \texttt{ativarCampainha()}: Ativa o alarme sonoro
    \item \texttt{desativarCampainha()}: Desativa o alarme sonoro
    \item \texttt{processarSensor(tipo, divisao)}: Processa notificação de sensor
    \item \texttt{resetTentativas()}: Reinicia o contador de tentativas
    \item \texttt{liga(senha)}: Alias para armar
    \item \texttt{desliga(senha)}: Alias para desarmar
    \item \texttt{getEstado(): bool}: Getter para estado
    \item \texttt{getEstadoCampainha(): bool}: Getter para campainha
    \item \texttt{getSenha(): string}: Getter para senha
    \item \texttt{getMensagem(): string}: Getter para mensagem
    \item \texttt{getTentativas(): int}: Getter para tentativas
    \item \texttt{getMaxTentativas(): int}: Getter para MAX\_TENTATIVAS
\end{itemize}

\begin{verbatim}

\end{verbatim}

\begin{itemize}
    \item \texttt{Sensor(id, divisao, tipo)}: Construtor

    \item \texttt{ativar()}: Ativa o sensor e notifica
    \item \texttt{desativar()}: Desativa o sensor
    \item \texttt{notificar()}: Envia notificação ao ComandoAlarme
    \item \texttt{fixaEstado(estado)}: Define o estado do sensor

    \item \texttt{getDivisao(): string}: Getter para divisão
    \item \texttt{getEstado(): bool}: Getter para estado
    \item \texttt{getTipo(): TipoSensor}: Getter para tipo
    \item \texttt{getTipoString(): string}: Getter para tipo em string
\end{itemize}

\section{Instalação e Compilação}

\subsection{Requisitos de Sistema}

Para compilar e executar o sistema de alarme, são necessários os seguintes requisitos:

\begin{itemize}
    \item \textbf{Compilador C++}: g++ com suporte a C++11 ou superior
    \item \textbf{Sistema Operativo}: Linux, macOS ou Windows (com MinGW/MSYS2)
    \item \textbf{Ferramenta Make}: GNU Make para automatização da compilação
    \item \textbf{Git}: Para controlo de versões (opcional)
\end{itemize}

\subsubsection{Opcao 1 - Armar Sistema}

Arma o sistema de alarme. Requer introduzir a senha de 4 dgitos.
A senha por omisso  \textbf{0000}.

\textbf{Exemplo de uso:}
\begin{verbatim}
Escolha uma opcao: 1
Introduza a senha: 0000
[ALARME] Sistema armado com sucesso
\end{verbatim}

\textbf{Caso de erro (senha incorreta):}
\begin{verbatim}
[ALARME] Senha incorreta para armar
\end{verbatim}

\subsubsection{Opcao 2 - Desarmar Sistema}

Desarma o sistema. Se a senha estiver incorreta 3 vezes, a campainha
ativa automaticamente.

\textbf{Exemplo de uso:}
\begin{verbatim}
Escolha uma opcao: 2
Introduza a senha: 0000
[ALARME] Sistema desarmado
\end{verbatim}

\textbf{Processo de tentativas:}
\begin{verbatim}
Escolha uma opcao: 2
Introduza a senha: 1111
[ALARME] Senha incorreta. Tentativas: 1

Escolha uma opcao: 2
Introduza a senha: 2222
[ALARME] Senha incorreta. Tentativas: 2

Escolha uma opcao: 2
Introduza a senha: 3333
[ALARME] CAMPANHA ATIVADA - ALARME SONORO
[ALARME] Tentativas: 3/3
\end{verbatim}

\subsubsection{Opcao 3 - Ativar Sensor}

Ativa um sensor especificado. Se o sistema estiver armado, o evento
dispara um alerta.

\textbf{Exemplo de uso:}
\begin{verbatim}
Escolha uma opcao: 3

--- SENSORES ---
Sensor 1: Sala | Movimento | INATIVO
Sensor 2: Cozinha | Gas | INATIVO
Sensor 3: Quarto | Intrusao | INATIVO
Sensor 4: Casa de Banho | Inundacao | INATIVO
Sensor 5: Entrada | Intrusao | INATIVO
ID do sensor a ativar: 1
[SENSOR 1] Ativado na divisao Sala
[ALARME] ALERTA: Sensor de Movimento ativado na divisao Sala
[ALARME] Introduza a senha para desarmar (3 tentativas):
\end{verbatim}

\subsubsection{Opcao 4 - Desativar Sensor}

Desativa um sensor que estava ativo.

\begin{verbatim}
Escolha uma opcao: 4
ID do sensor a desativar: 1
[SENSOR 1] Desativado
\end{verbatim}

Mensagem: Sistema armado com sucesso
\end{verbatim}

Lista todos os sensores com as suas caracteristicas.

\begin{verbatim}

Sensor 3: Quarto | Intrusao | INATIVO
Sensor 4: Casa de Banho | Inundacao | INATIVO

\end{verbatim}

\subsubsection{Opcao 7 - Mudar Senha}

Altera a senha do sistema. A nova senha deve ter exatamente 4 dgitos.

\textbf{Erro - Senha atual incorreta:}

\begin{verbatim}

\end{verbatim}

Termina a execucao do programa.

\end{verbatim}

% SECAO 5: FICHEIRO DE EVENTOS
\section{Formato do Ficheiro de Eventos}

\subsection{Estrutura e Funcionamento}

O ficheiro de eventos um ficheiro de texto simples onde cada linha representa
um comando a ser executado pelo sistema. Os eventos so processados por ordem de
chegada, seguindo a disciplina FIFO (\textit{First-In-First-Out}).

\subsection{Tipos de Comandos}

\begin{table}[h!]
\centering
\begin{tabular}{|l|l|p{6cm}|}
\hline
\textbf{Comando} & \textbf{Parametros} & \textbf{Descricao} \\
\hline
ARMAR & <senha> & Arma o sistema com a senha indicada \\
\hline
DESARMAR & <senha> & Desarma o sistema com a senha \\
\hline
MUDARSENHA & <senha\_antiga> <senha\_nova> & Altera a senha do sistema \\
\hline
ATIVAR & <id\_sensor> & Ativa o sensor com o ID especificado \\
\hline
DESATIVAR & <id\_sensor> & Desativa o sensor especificado \\
\hline
\end{tabular}
\caption{Tabela de comandos do ficheiro de eventos}
\end{table}

\subsection{Exemplo Completo de Ficheiro}

\begin{lstlisting}[caption={ficheiro eventos.dados - exemplo completo}]

# 3. Desarmar com senha correta

% SECAO 8: CONCLUSAO
\section{Conclusao}

O presente projeto de Sistema de Alarme Domestico representa a aplicacao pratica
dos conceitos fundamentais de Programacao Orientada aos Objetos utilizando a
linguagem C++. Atraves do desenvolvimento deste sistema, foram implementados e
consolidados diversos conceitos teoricos da disciplina.

\subsection{Conceitos POO Implementados}

O projeto evidencia a aplicacao dos seguintes pilares da programacao orientada
aos objetos:

\begin{enumerate}
    \item \textbf{Encapsulamento}: Cada classe expeem apenas interfaces publicas,
    mantendo os atributos privados e protegidos, garantindo a integridade dos
    dados e controlando o acesso aos mesmos.

    \item \textbf{Composicao}: A classe Simulacao e composta por objetos das classes
    ComandoAlarme e Sensor, estabelecendo uma relacao "tem-um" onde os componentes
    existem como parte integrant da classe container.

    \item \textbf{Associacao}: Os Sensores mantem uma referencia (ponteiro) ao
    ComandoAlarme ao qual estao associados, permitindo a comunicacao entre objetos
    de classes diferentes.

    \item \textbf{Gestao de Memoria}: Utilizacao adequada de ponteiros para gerir
    as associacoes entre objetos, garantindo o ciclo de vida correto dos mesmos.

    \item \textbf{STL (Standard Template Library)}: Implementacao pratica dos
    contentores std::queue (fila FIFO) e std::vector (colecao dinamica), demonstrando
    a capacidade de utilizar bibliotecas padrao da linguagem.
\end{enumerate}

\subsection{Resultados Alcancados}

O sistema desenvolvido cumpre todos os requisitos funcionais definidos no
enunciado do projeto:

\begin{itemize}
    \item Gestao de estados armado/desarmado
    \item Autenticacao por senha de 4 dgitos
    \item Controlo de campainha com 3 tentativas
    \item Suporte a 5 tipos de sensores
    \item Processamento de eventos em fila FIFO
    \item Interface de menu interativo
    \item Documentacao completa em codigo e manual
\end{itemize}

\subsection{Limitações e Trabalho Futuro}

Apesar de o sistema cumprir os requisitos especificados, existem areas que podem
ser melhoradas em trabalhos futuros:

\begin{itemize}
    \item \textbf{Heranca}: Implementar uma classe base Componente de onde derivem
    Sensor e ComandoAlarme, como sugerido na correcao do professor.

    \item \textbf{Persistência}: Adicionar gravacao e leitura de dados em ficheiros
    para manter o estado entre execucoes.

    \item \textbf{Interface Grafica}: Desenvolver uma GUI (Graphical User Interface)
    para substituir a consola de texto.

    \item \textbf{Múltiplos Utilizadores}: Implementar sistema de usuarios com
    diferentes niveis de acesso.

    \item \textbf{Timestamps}: Adicionar data e hora aos eventos para logs detalhados.

    \item \textbf{Tipos de Eventos}: Expandir os tipos de eventos suportados pelo
    sistema de simulacao.
\end{itemize}

\subsection{Tecnologias e Ferramentas Utilizadas}

O desenvolvimento do projeto utilizou as seguintes ferramentas:

\begin{itemize}
    \item \textbf{Linguagem}: C++11/14
    \item \textbf{Compilador}: g++ (GNU Compiler Collection)
    \item \textbf{Sistema Operativo}: Linux
    \item \textbf{Controlo de Versoes}: Git
    \item \textbf{Repositorio Remoto}: GitHub
    \item \textbf{Documentacao}: LaTeX (Overleaf)
    \item \textbf{Digramação}: PlantUML
\end{itemize}

\subsection{Agradecimentos}

Este projeto foi desenvolvido no ambito da unidade curricular de Programacao
Orientada aos Objetos, sob orientacao do corpo docente da instituicao.
